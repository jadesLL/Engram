所有结论必须来自用户提供的客户资料，注明来源文件；资料不足的结论明确标 `（推测，待验证）`。禁止编造数据。

## 排期规则（行动计划日期计算）

1. **锚点 D0 = 报告生成当天**。生成报告前先用 `date +%F` 获取当天日期。
2. **未来 90 天内**的每个动作都有明确的开始日期和完成日期（`YYYY-MM-DD`）。按动作类型给合理时长：
   - 资料补全/信息收集类：3-7 天
   - 拜访/会议类：从准备到闭环 7-14 天（准备 3-5 天 + 等待窗口 + 24h 内 CRM 记录 + 48h 档案更新）
   - 报告/评审类：7-15 天（撰写 + 评审会 + 按评审时效）
   - 大型项目/规划类：30-60 天，拆成多个里程碑动作
3. **避开周末**：日期落在周六/周日时顺延到下周一。
4. **90 天–1 年**：只给月度里程碑（`YYYY-MM` + 月内目标），不编造具体日期。
5. **频率型动作**（来自 ACS-04 时效铁律）写成周期动作并给首启日期，如"每周 1 次有效拜访（首启 2026-08-19，此后每周）"。
6. 依赖缺失资料的动作，完成日期不得早于对应缺失项的"建议完成日期"。
7. 缺失表单的"建议完成日期"同样具体到日，按优先级错峰：高（7-14 天内）、中（15-30 天）、低（30-60 天）。

## 质量自检（输出前）

- [ ] 每条关键结论都有来源标注或明确标注推测
- [ ] 行动计划 90 天内全部动作具体到日且不晚于依赖项日期
- [ ] 缺失表单覆盖三个 ACS 域（除非该域资料已完整）
- [ ] 决策链表至少识别出可识别的角色；识别不了的进缺失表单
- [ ] 日期均 ≥ D0，无周末（除非用户明确要求含周末）
