# ACS-02 管理联合创新 — 分析参考

> 依据：示例电气 ACS（助力客户成功）流程 0.5 版（试运行），ACS-02 域 = 管理联合创新。
> 适用范围：高价值 OEM 客户（经立项的 S、A 客户、高潜 B 级客户）。
> 用途：分析客户资料时，按本域四段子流程梳理"联合创新"现状，判断在途创新点是否健康，产出缺失资料清单与行动计划。
> 与相邻域分工：ACS-01 负责"洞察清楚"客户战略；ACS-02 负责"干出来"（识别创新价值—设计竞争力方案—落地方案—迭代方案）；ACS-03 管理客户战略合作。

## 1. 本域要回答的核心问题

分析客户资料时，应就以下问题形成判断（缺口即缺失资料清单条目）：

1. **客户战略中蕴含哪些可联合创新的点？** 客户实现战略目标（提升市场份额、降本等）过程中，有哪些具体、关键且尚未解决的难题？痛点是否真实对准客户战略？是否 EU 驱动？是否符合行业趋势？
2. **每个创新点属什么类型、值多少钱？** 是"人无我有（定制/创新）"还是"人有我优（改善/优化）"？TVO 价值是否量化成钱（多赚多少、省多少）？可推广性是 A/B/C 哪类？
3. **客户对创新机会的重视度和投入意愿如何？** 推动力是战略级/部门级/探索性？有无明确预算？客户项目有无明确时间节点（忌"尽快""待定"）？痛点是否来自关键决策角色？
4. **我司解决方案在该客户的竞争力如何？** 相对竞品的差异化优势是什么？功能/性能指标是否可衡量、可验证并与本公司现有及竞品 1/2 对比？有无战略控制点（护城河）与 CBB 复用？
5. **创新点是否通过了评审？** 在途创新点按"人无我有 5 维 / 人有我优 4 维"标准是否仍全部满足（无预算/无明确时间/非战略痛点/价值不明确者应驳回）？评审结论（通过/暂缓/关闭）是否在 CRM 留痕？
6. **在途开发验证项目的进展与风险如何？** 《项目详细计划书》的目标与 TVO 价值承诺（基线→目标→验证方法）、WBS 里程碑、资源预算、风险应对是否齐备且在跟踪？是否已取得客户验收（解决方案验证报告）？
7. **已批量运行的方案是否在持续优化闭环？** TVO 运行数据与 OEM/EU 关键岗位反馈是否定期收集？待优化问题是否完成根因分析—迭代实施—闭环验证？客户满意度是否达标？
8. **创新经验是否资产化？** 有无复盘报告、知识库案例、程序版本留存、成熟方案传播？

## 2. 分析框架：四段子流程

内部链条（依次为后段输入）：《创新合作机会清单》（02.01，战略源头文件）→《解决方案竞争力规划书》（02.02，商业决策文件）→《项目详细计划书》/《解决方案验证报告》（02.03，执行基准/价值证明文件）→《产品/解决方案优化清单》（02.04，持续改进文件）。回路：02.04 的客户声音与版本迭代需求回流前段（高优先级机会填 V2.0 需求表并上传机会清单）。

### 2.1 ACS-02.01 基于客户战略挖掘创新点

- **目的与关键活动**：深度解码客户战略，识别能为客户创造核心价值的潜在创新机会，评估客户技术需求创新性和价值。五步活动：① 深度理解客户战略、挑战和目标（输入《ACS客户洞察报告》）→ ② 交流客户、解码客户战略（AR 搭建对话通道，需求管理团队收集行业/市场/技术信息）→ ③ 量化价值、初步论证（评估创新点带来的 TVO 价值）→ ④ 与客户共识需求的创新性和价值（明确客户重视度、推动力、预算想法、预计时间）→ ⑤ 评审创新点（填《创新合作机会清单》提交 CRM，触发评审，结论通过/暂缓/关闭）。主责 PD；参与者 AR、SPD、需求管理团队、执行秘书。
- **分析资料时看什么**：有无《ACS客户洞察报告》（本域源头输入）；有无《创新合作机会清单》及 CRM 评审结论；清单是否覆盖"人无我有/人有我优"而非普通需求；痛点是否支撑客户战略；时间字段是否明确到节点。
- **关键工具字段 ——《创新合作机会清单》（16 字段，四大板块）**：
  - 基础信息：① 创新合作机会名称 ② 记录日期 ③ 项目类型（人无我有/人有我优）④ 原始需求来源角色（最终决策者、技术负责人、使用部门负责人等）⑤ 客户设备（设备 XX、机型 XX）。
  - 客户需求分析：⑥ 原始需求（保留客户原话，避免加工）⑦ 共识需求（对齐后的精准描述）⑧ 客户项目明确时间/期望完成时间（例：2026 年 Q3 前验收）⑨ 客户战略痛点（例：降本 15% 目标下的设备能耗过高）⑩ 是否 EU 驱动 ⑪ 是否符合行业趋势（符合/部分符合/不符合）。
  - 价值评估：⑫ 为 OEM 客户带来 TVO 价值（价值主张/具体描述/收益量化 TCO-TVO，如"零件节省 4500 元"）⑬ 经济价值（我司预估合同金额，按自然年、从投产起）⑭ 可推广性（A 类可产品化多客户复用 / B 类单客户高价值 / C 类一次性定制须说明特殊战略价值）。
  - 可行性初步评估：⑮ 客户重视度与预算（战略级/部门级/探索性 × 明确预算/意向预算/无预算）⑯ 竞争态势（其他品牌方案做到什么程度、竞品商务竞争力、竞品教练或排斥本公司的人员）。

### 2.2 ACS-02.02 解决方案竞争力规划

- **目的与关键活动**：将选定的创新合作机会转化为有明确差异化优势和商业竞争力的解决方案沙盘，并制定确保竞争力实现的内外部全面规划。五步：① 竞品深度分析与核心竞争力锚定 → ② 制定方案实施策略（开发规划、价格策略、产品方案策略、资源预算、风险评估）→ ③ 编写《解决方案竞争力规划书》→ ④ 内部评审并获预算与资源初步承诺（决策点：项目立项、公司承诺资源、PD 组建客户项目团队并获团队成员考核评价权）→ ⑤ 与客户共识解决方案与规划。主责 PD；参与者 SPD、AR、行业线/产品线。
- **分析资料时看什么 —— 规划书"四问"是否都有答案**：
  - 第 0 问"我们要打什么仗？"：战场与目标方向，信息来自《ACS客户洞察报告》与《创新合作机会清单》。
  - 第 1 问"我们凭什么能赢？"：差异化优势（技术方案/成本/服务）、量化竞争力指标、竞争策略（领先者/挑战者/追随者）。
  - 第 2 问"我们该怎么打？"：开发规划、商务策略、资源与预算、风险评估与应对。
  - 第 3 问"这仗值得打吗？"：对客户的价值 + 对我司的经济价值（预期收入、利润）与战略价值（市场卡位、技术标杆）对比投入成本。
- **关键工具章节 ——《解决方案竞争力规划书》（0-4 章）**：
  - 第 0 章基于客户战略挖掘创新机会：客户设备重要性（机型分层 H1 主力/H2 开发/H3 未来布局，销售额、增长率、生命周期、电气用量与现供商）；客户需求和创新方案（创新来源、原始需求、初步方案、创新点价值、创新等级=局部优化/关键点突破/颠覆）；创新为客户实现的 TVO 价值（价值主张、具体描述、收益量化、差异化竞争力）。
  - 第 1 章解决方案竞争力构想：1.1 设备工艺分析与难点｜1.2 系统配置（工位×产品配置）｜1.3 工艺难点逐一分析（多方案对比，选型有结论）｜1.4 战略控制点（制高点工艺、验收标准、规划实现时间、竞争现状、本公司差距、能力要求）｜1.5 功能构想（可衡量可验证即验收标准、创新性、竞对方案、对产品需求）｜1.6 性能构想（速度/精度/效率/故障率/能耗等按重要性排序，对比本公司现状与竞品 1/2）｜1.7 功能性能复用（CBB 模块名称、覆盖范围）｜1.8 竞争力里程碑（分一/二阶段）｜1.9 对产品需求（按信息/控制/驱动/执行/感知层汇总，含经济价值、最佳落地时间、是否已立项）。
  - 第 2 章实施路径：2.1 开发周期任务和责任人（里程碑×完成标准×工时）｜2.2 资源投入（分年度预算：收入、人力成本、实验设备等）｜2.3 风险评估（风险/困难求助/申请决策 × 领域 × 应对措施 × 闭环责任人与时间，必须有结论）。
  - 第 3 章商业价值（公司视角）：战略价值（战略落地、技术沉淀）+ 市场价值（直接营收、品牌增值/赛道拓展、客户粘性成为战略客户）。
  - 第 4 章其他：待决策事项。

### 2.3 ACS-02.03 开发和验证解决方案

- **目的与关键活动**：将方案构想转化为可落地验证的实体解决方案，在客户真实场景测试，验证有效性、稳定性、业务价值，获取客户关键认可。五步：① 启动项目、制定详细计划并拉通客户 → ② 方案开发与内部验证（区域自行方案型必须备图纸、电路图、程序）→ ③ 客户现场部署与联合验证（部署四要素：线路、设备机构、人员和时间、测试物料；与 OEM+EU 做业务场景测试与关键数据验证如速度、精度）→ ④ 问题修复与优化、客户验收通过 → ⑤ 总结复盘。主责 SPD；参与者 AR、产品线/行业线（研发）、客户技术负责人。
- **关键控制点**：详细计划内外部拉通并与客户共识；内部验收标准达成；客户环境部署提前确认；联合测试与验证、验收报告签署确认；问题修复与优化（OEM+EU）；TVO 价值验证。
- **分析资料时看什么**：有无《项目详细计划书》且与规划书对应；目标是否有基线和验证方法；WBS/里程碑/责任人/状态是否在跟踪；有无验证测试报告、关键数据记录、客户验收报告；问题清单是否闭环。
- **关键工具字段 ——《项目详细计划书》（四部分）**：
  - 一、项目目标与价值承诺：关键指标｜基线（现状）｜项目承诺目标｜验证方法（客户 TVO 例：OEE 65%→≥78%，验证=客户 SCADA 数据对比；本公司战略目标例：打造行业标杆案例）。核心团队四角色：SPD（项目负责人）、开发代表、AR、客户技术负责人。
  - 二、任务分解与关键里程碑：WBS｜关键活动/交付物｜责任人｜计划开始/完成日｜状态。预置 WBS：启动会、软件开发、硬件组装与内部测试、《内部测试报告》、方案准备（图纸/电路图/程序）、现场部署调试、《联合测试方案》客户确认、联合测试与数据采集、《解决方案验证报告》初稿、问题修复与优化、客户验收签署。
  - 三、资源与预算：人力资源（人月）、物料成本、差旅与实验、总预算。
  - 四、风险与策略：风险描述｜概率｜影响｜应对策略｜负责人（例：客户测试窗口不足、数据达不到承诺 OEE、关键元器件延迟）。
- **配套输出**：《版本发布说明》《算法版本》《电气原理图》《程序版本》《验证测试报告》《关键数据记录》《问题收集及优化清单》《客户验收报告》《操作说明书》《解决方案复盘报告》《程序版本方案留存》。其中《解决方案验证报告》是价值证明文件——证明达成预期 TVO 价值、获客户正式验收的关键凭证。

### 2.4 ACS-02.04 持续优化解决方案

- **目的与关键活动**：方案通过验证批量推广后，持续收集核心数据（TVO 相关），定期收集 OEM 和 EU 关键岗位反馈，组织团队分析根因、输出迭代路径并实施闭环，最终持续提升方案竞争力。六步：① 优化迭代信息收集筛选汇总（满意度反馈表、运行日志 → 待优化信息汇总表）→ ② 差距分析与优化实施路径输出（联合研发做根因分析）→ ③ 迭代方案实施落地（组建迭代项目组，评审—实施—落地）→ ④ 迭代方案验证（对比预期关键数据）→ ⑤ 知识资产化（案例入库）→ ⑥ 传播（成熟方案与方法分享）。主责 SPD；参与者 PD、FR、AR、行业线/产品线、研发经理、区域经理。关键要求：数据真实、高质量、有代表性；不间断循环"信息收集—根因分析—迭代设计实施—闭环校验和归纳传播"。
- **分析资料时看什么**：有无方案运行日志与关键数据收集表；OEM/EU 关键技术和工艺人员对质量、操作便利性、稳定性的反馈是否定期收集；有无待优化信息汇总、差距分析报告、迭代项目进度与验收；满意度是否"超出/达到预期"；有无知识库案例与传播记录。
- **关键工具字段 ——《产品/解决方案优化清单》**：
  - 第 1 部分迭代信息收集和输出（7 列）：客户方案满意度（超出/达到/不及预期/严重不达预期）｜客户和 EU 建议反馈（精度、速度、操作便捷性等）｜方案可优化点（bug 或不满足要求的原因）｜目前竞品方案达成情况｜不优化造成的影响｜优化标准制定（验收标准）｜预计所需时间。
  - 第 2 部分项目验收单（6 行验收标准）：优化成果=既定输出标准；方案交付质量（行业/产品线）；问题解决情况；交付质量（客户）；交付满意度；其他约定。每行记验收结果（合格/不合格/整改中）、备注、负责人签字、日期。

## 3. 创新点评审双轨标准

判断"在途创新点是否健康"的依据：所有创新点须过双轨评审，评审重点是创新性（方向），而非普通需求排序。

**双轨定义**：
- 人无我有（创新/定制）：客户要求的功能或方案，目前我司及竞品均不具备，需投入较多研发资源；必须见客户专项预算或人力投入承诺。
- 人有我优（改善/优化）：我司已有方案，客户要求在性能、体验、成本等方面优化，无需新增核心功能；不强制客户专项预算，但需确认客户有内部资源配合（测试人员、试点场地等）。

**表 1：人无我有（定制、创新）— 5 个评审维度**（5 项全部满足方可通过）：

| 维度 | 判断标准（原文要义） | 驳回/暂缓规则 |
|---|---|---|
| 1 预算 | 客户已规划专项项目（目标、项目经理）、成立专项部门、投入专项人力/资金等实际行为 | 无明确预算 = 驳回 |
| 2 时间 | 客户项目有明确期望完成时间、开发/采购计划，启动、验收、下单等关键节点清晰 | 无明确时间、无限期推迟 = 驳回 |
| 3 权限 | 已识别关键决策角色（最终决策者、技术选型者、使用部门负责人），并至少与一位建立有效沟通渠道 | 决策人暂未明确 = 暂缓 |
| 4 需求 | 客户明确必须解决的业务痛点，是支撑客户战略实现的重要环节，满足"联合创新"定义 | 非战略痛点、伪需求、不满足联合创新定义 = 驳回 |
| 5 价值 | TVO 价值明确且可提升客户行业竞争力；可推广性分 A 类（资源倾斜优先支持）/B 类（可通过但须说明高价值）/C 类（原则上驳回，除非特殊战略意义需上升决策） | TVO 不明确 = 驳回；C 类战略价值不明显 = 驳回 |

**表 2：人有我优（改善、优化）— 4 个评审维度**（4 项全部满足方可通过）：时间、权限、需求、价值四维，判断标准同表 1（价值维度 TVO 引用《TVO价值量化表》）。

**结论与表决规则**：结论为通过 / 暂缓（补充后重提）/ 关闭（驳回归档）；有争议时上升决策；举手表决，按奇数同意判定结论（评审团队须为奇数 ≥3 人，且必须包含 PD 直属上级；需求有行业属性时必须先拉行业线经理及以上共识需求，再对接产品线，不可跳过行业拉产品线）。

**时效要求（分析在途点是否超期的标尺）**：
- PD 提报后，AI + PD 直属上级 2 天内完成初审；初审通过后 3 天内 PD 发起评审会。
- 评审结束 1 小时内执行秘书在 CRM 录入结果、意见、理由，留痕不可篡改。
- 暂缓项：PD 5 天内补充重提，指定审核人 1 天内完成确认；超期未补视为自动关闭。
- 争议项：3 天内发起上升评审（行业线经理/高级经理 1-2 位、产品线高级经理 1-2 位、销服大区总监，奇数 ≥3 人），必须当场一锤定音，不拖延不复议；再有争议由大区总监上升汇报总经理。

## 6. 术语表

- **ACS-02 管理联合创新**：我司与客户围绕设备工艺创新，进行产品级深度定制、行业解决方案共创、技术前瞻性预研、生态与品牌联合，共同投入资源，产生可验证商业成果，实现"强强联合、价值共创"的合作创新模式（改善、迭代也属于创新）。
- **解决方案（广义）**：基于客户工艺与市场需求，硬件/软件层面的本公司综合成套方案，含通用品、行业专机、定制机、工艺算法等；分整体式、单产品、单方案型三类。
- **人无我有（创新/定制）**：我司及竞品均不具备的功能或方案，需投入较多研发资源，必须见客户专项预算或人力投入承诺。
- **人有我优（改善/优化）**：我司已有方案，客户要求性能/体验/成本优化，无需新增核心功能；不强制客户专项预算，但需客户内部资源配合。
- **TVO 价值**：总体价值贡献 Value，把产能提升、省人、次品率降低等换算成钱呈现给客户（"多赚/省多少"）。
- **TCO 价值**：总体拥有成本 Cost，直接（采购价、运输、安装）+ 间接（培训、维护、空间）成本。
- **可推广性 A/B/C 类**：A=可产品化多客户复用（价值最高）；B=单客户高价值；C=一次性定制无复用（须说明特殊战略价值）。
- **创新等级**：局部优化 / 关键点突破 / 颠覆。
- **客户设备机型分层**：H1 主力机型 / H2 开发机型 / H3 未来布局机型。
- **战略控制点**：解决方案的护城河——制高点工艺，让企业领先对手且不易被模仿或超越。
- **CBB**：可复用/模块化封装的功能性能模块（如采样算法、张力控制、防摇算法、锂电卷绕算法）。
- **PD / SPD / AR / FR / 研发代表 / 执行秘书 / 需求管理团队**：PD=客户第一责任人；SPD=客户解决方案第一责任人；AR=客户关系第一责任人；FR 仅大型客户特定场景出现；执行秘书=支持 PD、记录评审并在 CRM 上传结论；需求管理团队=区域细分行业 SPD+产品线+行业线的完整团队。
- **OEM / EU**：OEM=设备制造商客户；EU=终端用户（End User）。
- **行业线 / 产品线**：行业线=所辖行业解决方案全国/区域市场占有率第一责任人；产品线 PD=所辖产品竞争力第一责任人。
- **评审结论三态**：通过（进入后道流程）/ 暂缓（补信息后重提）/ 关闭（归档终止）。
- **五大工具文件**：创新合作机会清单（战略源头）、解决方案竞争力规划书（商业决策）、项目详细计划书（执行基准）、解决方案验证报告（价值证明）、产品/解决方案优化清单（持续改进）。
