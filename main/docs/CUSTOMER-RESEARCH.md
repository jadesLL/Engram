# 客户调研

桌面版与 Docker 网页共用客户调研服务；Android 安装版绑定中枢后可查看、启动、停止调研和修改流程模板，由中枢执行 Agent 并保存报告，原始资料按同步分类设置同步到手机。主导航打开「客户调研」，输入客户全名或简称，选择「知识库 + 联网调研」或「仅知识库资料」，点击「调研并保存」。需先在桌面端或中枢的「设置 → Agent 与自动化」配置内置 Agent。

报告按 v2 契约生成：**先核验客户主体 → 再按证据量选报告模式 → 只写能指回来源的结论**。公开工商与知识库都确认不了主体时，只出「主体核验」短报告并明确质疑客户是否存在、名称是否写错，不写客户分析、不保存文件。

## 多端同步

设置 → 多端同步 → 同步内容 里的「客户洞察多端同步」默认开启。同步的是**调研记录本身**（客户、报告正文、生成日期、流程版本、主体核验结论与已保存的原始资料路径）和**流程与模板**（流程正文 + 8 个固定章节标题）：同步群组内任意一端发起的调研，其余端在客户洞察页都能按客户看到；在任一端改的流程模板，其余端下一次调研即生效，已开始的任务仍保留自己的规则快照。

- **只同步完成态**：已生成报告（含未保存的草稿报告）才跨端；进行中、排队或失败的记录留在执行端，不会在别的设备上显示成一条永远转圈的「进行中」。报告正文与主体核验结论随记录同步，因此即使关闭「原始资料」分类，对端也能在客户洞察里翻阅报告、看到「主体未核实」等警示；已保存的报告文件本身仍走原始资料同步。
- **冲突**：同一任务按记录更新时间「最新者胜」；流程模板按最近一次保存时间取值（与设置类内容相同口径）。
- **Android**：手机端不落调研记录副本，读写都经窄代理直接访问已绑定的中枢（与手机会话、任务看板同一方式），所以手机看到的始终是中枢最新数据；未绑定中枢时无法离线查看客户洞察。

## 流程与报告

### 第一步：核验客户主体

先核对输入名称对应的主体是否存在，再决定写什么；核验结论随报告一起提交（提交契约里的 `identity`）：

- **verified（已核实）**：在公开工商登记或官方渠道找到该主体。尽量拿到工商全名填 `fullName`（保存命名与报告抬头都用它），能拿到统一社会信用代码就填 `registrationId`；`evidence` 指向 kind=registry（企查查/天眼查/国家企业信用信息公示系统等）或 kind=official（官网/年报/公告等）的外部来源。仅「知识库 + 联网调研」范围可声明 verified。
- **kb-docs（仅库内资料）**：外部没核实到，但知识库里确有该客户的实质原始资料（拜访纪要、合同、报价、往来记录）。`evidence` 至少 1 条必须是 `原始资料/` 下的原始文档；只有 Wiki 页面、客户名单或名称提法不算主体证据，不能据此补全客户分析。
- **not-found（查无此主体）**：公开渠道与知识库都确认不了主体。必须列出至少 2 次检索尝试（不同渠道或关键词），`evidence` 留空并写清判定原因（`note`），只提交「主体核验」短报告；报告会明确说未能核实该客户是否存在、名称是否写错或只是品牌简称，不写任何客户分析。客户洞察页会在报告前亮出「查无此主体」警示、判定原因与检索记录，并按当前客户名提供重新发起调研的入口。

「仅知识库资料」范围不能声明 verified；「知识库 + 联网调研」但公开资料不足时按 kb-docs 或 verified+简报处理，不硬凑完整版。

### 第二步：按证据量选报告模式

服务端按 `identity.status` 与提交的章节集合推断模式，不靠模型自觉：

| 模式 | 适用 | 章节（每章正文上限，字） |
| --- | --- | --- |
| 完整报告 | 仅「知识库 + 联网调研」且 verified；来源 ≥3 条、外部来源 ≥2 条、其中至少 1 条工商/官方来源，「已核实事实」≥2 处引用、「需求与机会」≥1 处引用 | 结论 400 / 客户主体与核实 900 / 已核实事实 1200 / 需求与机会 1200 / 决策链与关系 900 / 风险与反证 700 / 下一步行动 1000 / 待核实 700 |
| 资料不足简报 | 「仅知识库资料」、kb-docs，或已核实主体但公开资料不够写完整版 | 结论 350 / 已知事实 800 / 待核实 500（「已知事实」至少 1 处引用） |
| 主体核验 | not-found：公开工商与知识库都确认不了主体 | 核验结论 300 / 需要你确认 300；「核验过程」由服务端按检索尝试生成 |

完整版达不到来源或引用门槛会被拒收并提示改交简报；简报与主体核验的章节标题固定，完整版的 8 个章节标题可在「流程与模板」里改。

### 第三步：只写有依据的结论

- 结论先行；只写与该客户直接相关、能指回来源的事实，正文用 `[来源编号]` 引用；超出长度上限或引用不存在的来源会被拒收。
- 推断标「推断」，不确定写「待核实」；没有的写没有，不用「行业趋势 / 市场空间 / 国产替代」这类通用叙述填充。
- 禁止方法论、能力声明、检索过程与免责声明等元叙述（范围与来源统计由服务端页头生成），也禁止「本章主要…」「综上所述」「随着…发展」「具有重要意义」这类版面话术与空话。
- 正文不要再写 `#`/`##` 标题，标题由模板生成。

### 保存与命名

- 完整报告存 `原始资料/文档/YYYY.MM.DD_<工商全名>调研报告.md`；资料不足简报存 `原始资料/文档/YYYY.MM.DD_<工商全名或客户名>调研简报.md`；主体核验只留调研记录，不保存文件。
- 日期取任务开始时用户时区的自然日；重名依次追加 `_2`、`_3`（例如 `2026.01.01_某某有限公司调研报告_2.md`），已有文件及回收站中的同名报告均不覆盖。
- 一份任务只对应一份完成态报告：重复提交同一份内容返回已保存路径，改动内容会报「已保存报告不可覆盖」，需要新一轮请重新发起调研。保存失败不标成功。
- 客户洞察页任务状态：`报告已保存` / `报告待保存`（未保存草稿）/ `主体未核实`（主体核验报告）；执行中、失败、停止等状态沿用 Agent 会话状态。

### 流程与模板

「流程与模板」可修改流程正文和 8 个章节标题。内置与外部 Agent 每次开始任务都读取同一版本，已开始的任务保留自己的规则快照；完整版按快照里的标题渲染，简报/主体核验用固定标题。章节标题不能重复，也不能用「来源与结论对照」（该章由系统固定生成）。

**旧模板升级**：v1 的八章 ACS 流程模板没有 v2 契约标记，服务端读取时会按默认 v2 模板（流程正文 + 8 个章节）重建并把模板版本 +1；用户在旧模板里自定义的流程正文与章节标题会一并重置，需要重新填写。历史报告的「流程版本」仍按任务快照显示。

## 外部 Agent

统一 MCP 入口 `begin_customer_research(customer, scope, client?, timeZone?, save?)`：返回任务 ID、流程正文、模板版本、`identityContract`（主体核验要求）、`reportContract`（三种模式的章节、每章上限、来源格式）与 `modeRules`（何时用哪种模式）；`submit_customer_research` 校验通过后才算完成。客户端入口 skill 只说明何时调用，契约以服务端返回为准，不在客户端复制一份。

`submit_customer_research(taskId, identity, sections, sources, save?)`：

- **identity 必填**（v1 的 `companyFullName` 会被明确拒绝）：`status`=verified / kb-docs / not-found，`method`=registry / official-site / kb-documents / none，`attempts` 1–12 条检索记录，`evidence` 指向 sources 里的来源编号；verified 还要 `fullName`（可带 `registrationId`）。
- **模式由 status + 章节集合推断**：not-found 只接受 `summary`/`gaps` 两章；完整报告除 8 章外还要满足上面的来源与引用门槛；其余为三章简报。模式不符会返回明确的修正提示，按提示改交对应模式，不要绕过校验改用 `create_raw_material`。
- **sources** 每条 `{id, title, url 或 path（只能二选一）, kind: registry|official|media|kb-doc|kb-page, publishedAt, accessedAt}`；「仅知识库资料」不能带 url；kb-docs 证据必须含 `原始资料/` 下的原始文档且不得掺外部网页；verified 仅限「知识库 + 联网调研」。
- **保存语义**：内置「调研并保存」按钮已授权保存；外部对话只有在用户明确要求保存时才传 `save=true`，其余默认只出报告预览（可在客户洞察翻阅）。not-found 永不保存文件。结构校验不证明事实真伪，网页来源仍需 Agent 实际阅读核查。

在「设置 → Agent 与自动化 → 外部 Agent 接入」重新注册：

| 客户端 | 客户调研触发入口 |
| --- | --- |
| Codex | 用户级 `.agents/skills/engram-customer-research/SKILL.md` |
| ZCode | `.zcode/skills/engram-customer-research/SKILL.md` |
| DeepSeek Harness（dsh） | `$DSH_HOME/skills/engram-customer-research/SKILL.md` |
| WorkBuddy | 用户级 `.codebuddy/skills/engram-customer-research/SKILL.md`（兼容其 CodeBuddy 配置） |
| Kimi Code CLI | `$KIMI_CODE_HOME/skills/engram-customer-research/SKILL.md`（默认 `.kimi-code`） |
| Kimi Work | Engram 个人插件的 `skillInstructions`；重新登记后仍需在 Kimi Work 安装插件 |

入口 skill 只包含何时使用和如何调用，不复制流程与契约全文，不含 Token。重新注册不会覆盖用户自行创建的同名技能；注销只删除带 Engram 管理标记的入口。Docker 的一键注册只作用于服务端所在机器，不能替远程电脑改配置；远程客户端使用配置片段，并复制或导入入口 SKILL.md。

外部聊天说「调研客户 A」时默认返回报告预览；说「调研并保存」或之后要求保存时，Agent 才提交 `save=true`。不自动更新客户实体页。自然语言自动触发依赖客户端是否加载了 skill 和模型是否遵循规则；可用客户端的显式 skill 命令减少漏选，不能把配置写入成功等同于真实模型已调用。
